\## minitor-gui 优化建议（Rust + egui 实战指南）



\## 一、内存优化（目标：70 MB → 40 MB 以下）



\### 1. 字体子集化（最大收益，预计省 15–20 MB）



微软雅黑 19 MB 是最大头。用 `fonttools` 生成只包含监控界面所需字符的字体子集：



```bash

\# 提取监控界面需要的字符（ASCII + 常用中文 + 特殊符号）

fonttools subset msyh.ttc --text-file=chars.txt --output-file=msyh-min.ttf

\# chars.txt 内容：CPU内存磁盘网络温度风扇电池进程GPU温度频率↑↓→←█░▒▓●○% / GB MB KB RPM °C

```



然后在 Rust 侧只加载子集字体：



```rust

// 替代 ctx.set\_fonts 加载完整字体的逻辑

let mut fonts = egui::FontDefinitions::default();

fonts.font\_data.insert("msyh\_mini".to\_owned(), 

&#x20;   egui::FontData::from\_static(include\_bytes!("../assets/msyh-min.ttf")));

fonts.families.entry(egui::FontFamily::Proportional)

&#x20;   .or\_default().insert(0, "msyh\_mini".to\_owned());

ctx.set\_fonts(fonts);

```



\### 2. 历史数据降采样（预计省 5–10 MB）



当前 60 秒窗口 × 1 fps × 多指标，数据结构如果每帧都 push 一个新 Vec 会很浪费。建议：



```rust

// 使用环缓冲区替代 VecDeque（固定容量，零分配）

pub struct FixedRing<T, const N: usize> {

&#x20;   buf: \[MaybeUninit<T>; N],

&#x20;   head: usize,

&#x20;   len: usize,

}



// 60秒窗口，1fps，最多60个点，编译期确定大小

pub struct MetricHistory {

&#x20;   cpu: FixedRing<f32, 60>,

&#x20;   mem: FixedRing<f32, 60>,

&#x20;   net\_down: FixedRing<f32, 60>,

&#x20;   net\_up: FixedRing<f32, 60>,

&#x20;   disk\_read: FixedRing<f32, 60>,

&#x20;   disk\_write: FixedRing<f32, 60>,

&#x20;   temp: FixedRing<f32, 60>,

}

```



\### 3. 进程快照复用（避免每帧全量分配）



进程列表如果每帧都 `Vec::new()` 重新收集，463 个进程 × 8404 线程会产生大量短生命周期分配。建议：



```rust

pub struct ProcessCache {

&#x20;   // 复用 Vec 容量，clear 而非重新分配

&#x20;   processes: Vec<ProcessInfo>,

&#x20;   // PID → 静态信息（名称、路径、图标）只采集一次

&#x20;   static\_info: HashMap<u32, Arc<ProcessStatic>>,

}



impl ProcessCache {

&#x20;   fn refresh(\&mut self) {

&#x20;       self.processes.clear(); // 保留容量

&#x20;       // ... 填充新的进程数据

&#x20;       // 清理已退出进程的静态信息（定期执行，不必每帧）

&#x20;   }

}

```



\### 4. egui 纹理缓存清理



egui 的 `Context` 内部会缓存绘制的纹理。如果图表区域频繁 resize，旧纹理可能滞留。在 `App::update` 末尾：



```rust

// 每 100 帧清理一次未使用的纹理

if self.frame\_count % 100 == 0 {

&#x20;   ctx.purge\_cache(); // egui 0.27+ 提供

}

```



\### 5. 编译优化（免费的内存+性能提升）



```toml

\[profile.release]

opt-level = "z"       # 或 "s"，优先代码大小

lto = true

codegen-units = 1

strip = true

panic = "abort"

```

\## 二、主题默认系统主题



\### 实现方案



Windows 暗色模式注册表键：`HKEY\_CURRENT\_USER\\Software\\Microsoft\\Windows\\CurrentVersion\\Themes\\Personalize`，值 `AppsUseLightTheme` = 0 表示暗色。



```rust

use windows\_registry::Value;



fn get\_system\_theme() -> Theme {

&#x20;   let hkcu = windows\_registry::CURRENT\_USER

&#x20;       .open("Software\\\\Microsoft\\\\Windows\\\\CurrentVersion\\\\Themes\\\\Personalize")

&#x20;       .ok();

&#x20;   match hkcu.and\_then(|k| k.value("AppsUseLightTheme").ok()) {

&#x20;       Some(Value::U32(0)) => Theme::Dark,  // 0 = 暗色

&#x20;       \_ => Theme::Light,                    // 1 = 浅色

&#x20;   }

}



// 启动时读取

let theme = get\_system\_theme();

ctx.set\_visuals(match theme {

&#x20;   Theme::Dark => egui::Visuals::dark(),

&#x20;   Theme::Light => egui::Visuals::light(),

});

```



> \*\*注意\*\*：需要 `windows-registry` crate（Windows 官方维护，零额外依赖体积）。

\## 四、散热温度曲线 Y 轴下限调整



\### 问题分析



当前 30–100°C 的刻度在低负载时（76°C），曲线被压缩在上半部分，浪费了下半区域。



\### 解决方案：动态自适应刻度



```rust

pub struct TempAxis {

&#x20;   pub min: f32,

&#x20;   pub max: f32,

}



impl TempAxis {

&#x20;   /// 根据当前温度动态计算合适的刻度范围

&#x20;   /// 策略：下限取 当前温度-15 和 30 的较大值，上限取 当前温度+15 和 100 的较小值

&#x20;   /// 保证至少有 30°C 的显示范围

&#x20;   fn adaptive(current: f32) -> Self {

&#x20;       let range = 40.0; // 固定显示 40°C 范围

&#x20;       let half = range / 2.0;

&#x20;       let mut min = (current - half).max(25.0);

&#x20;       let mut max = min + range;

&#x20;       if max > 105.0 {

&#x20;           max = 105.0;

&#x20;           min = max - range;

&#x20;       }

&#x20;       Self { min, max }

&#x20;   }

}

```



这样在正常办公时（70–80°C），刻度自动聚焦在 50–95°C 区间，曲线变化更明显。高负载或高温时自动扩展。

\## 六、网络/磁盘图表颜色与峰值问题



\### 1. 颜色区分度



当前上行/下行、读/写颜色太接近。建议：



| 指标 | 推荐颜色（深色主题） | 推荐颜色（浅色主题） |

|------|---------------------|---------------------|

| 网络下行 | `#4FC3F7`（亮蓝） | `#1976D2`（深蓝） |

| 网络上行 | `#FF7043`（珊瑚橙） | `#E64A19`（深橙） |

| 磁盘读取 | `#66BB6A`（翠绿） | `#2E7D32`（深绿） |

| 磁盘写入 | `#FFA726`（琥珀黄） | `#F57F17`（深黄） |



```rust

// 用 egui 的 alpha 区分填充和线条

let down\_fill = egui::Color32::from\_rgba\_premultiplied(79, 195, 247, 40); // 低透明度填充

```



\### 2. 峰值自动缩放（"不能在峰值点"问题）



核心问题：如果 Y 轴上限是固定值（如峰值），数据没有更新时曲线就一直贴顶。



```rust

pub struct AutoScale {

&#x20;   current\_max: f32,

&#x20;   target\_max: f32,

&#x20;   /// 平滑因子：值越大，缩放变化越慢（避免抖动）

&#x20;   smooth\_factor: f32, // 建议 0.1 \~ 0.2

}



impl AutoScale {

&#x20;   fn update(\&mut self, current\_value: f32) {

&#x20;       // 动态目标：取最近 N 个采样的最大值，或当前值的 1.2 倍

&#x20;       let ideal\_max = (current\_value \* 1.2).max(self.recent\_peak());

&#x20;       // 平滑过渡，避免刻度跳变

&#x20;       self.current\_max += (ideal\_max - self.current\_max) \* self.smooth\_factor;

&#x20;   }

&#x20;   

&#x20;   fn recent\_peak(\&self) -> f32 {

&#x20;       // 从环缓冲区取最近 30 个点的 90 分位值

&#x20;       self.history.percentile(0.9)

&#x20;   }

}

```



> \*\*关键点\*\*：Y 轴上限应该跟随\*\*近期数据的动态峰值\*\*（如最近 30 秒的 P90），而不是全局历史最大值。这样空闲时图表会自动收缩到合适范围，不会出现"贴天花板"的情况。

\## 九、GPU 监控模块（新增）



\### 采集方案选择



| 方案 | 优点 | 缺点 | 推荐度 |

|------|------|------|--------|

| \*\*DXGI\*\* | 零依赖，可获取 GPU 名称、总显存 | 无法获取 GPU 占用率、当前显存使用量 | 基础必备 |

| \*\*PDH 计数器\*\* | 零依赖，可获取 GPU 引擎利用率、进程显存 | Windows 10 1709+ 才有 GPU 计数器 | 核心推荐 |

| \*\*NVML\*\* | 最完整（NVIDIA 专用） | 需要加载 nvml.dll，仅 NVIDIA | 可选 feature |
