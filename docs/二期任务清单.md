# 二期任务清单

目标：补齐任务管理器里 minitor 还缺的信息（硬件明细、Wi-Fi 详情、GPU、进程），并把外壳做成可长期常驻的形态。
原则：**不引入第三方 crate**，全部用 Win32 / PDH / NT 原生接口；TUI 的零依赖不变，GUI 已有的 eframe 不变。

## 总览

| 里程碑 | 内容 | 工作量 | 依赖 |
| --- | --- | --- | --- |
| **M1** | 硬件信息（主板 / BIOS / 内存条 / 磁盘型号） | 0.5–1 天 | — |
| **M2** | Wi-Fi 与网络详情（SSID / 信号 / IP / 链路速率） | 0.5 天 | — |
| **M3** | GPU 监控（利用率 / 显存） | 1 天 | M1 的页面框架（可选） |
| **M4** | 进程管理（列表 / 排序 / 搜索 / 结束进程） | 1.5–2 天 | M1 的页面框架 |
| **M5** | 开机自启 / 单实例 / 托盘（收尾） | 1 天 | — |

界面会新增"页面"概念：`总览`（现有六卡片）/ `硬件` / `进程`，顶部切换。M1 顺手搭好，M3/M4 往里填。

## M1 硬件信息

**要显示的**：主板厂商/型号、BIOS 版本/日期、内存插槽（已用/总数、每条容量、速度 MT/s、厂商、型号）、磁盘型号。

- [ ] `sys/smbios.rs`：`GetSystemFirmwareTable('RSMB', 0, …)` 取原始 SMBIOS 表，解析结构头 + 字符串表
  - Type 0（BIOS）：厂商、版本、发布日期
  - Type 2（Baseboard）：厂商、产品名、版本
  - Type 16（Physical Memory Array）：槽位总数、最大容量
  - Type 17（Memory Device）：单条容量、速度、厂商、Part Number、Bank；注意 SMBIOS 3.0 的 `ExtendedSpeed`（偏移 0x54）优先于旧 `Speed`
  - 校验：长度字段、字符串索引落在字符串表内，坏数据直接跳过而不是 panic
- [ ] `sys/disk.rs` 扩展：读 `HKLM\SYSTEM\CurrentControlSet\Services\disk\Enum`，从 `SCSI\Disk&Ven_SAMSUNG&Prod_MZVLB512HBJQ-000L7\…` 解析出盘型号（免管理员、免 WMI）
- [ ] GUI：新增 `硬件` 页，分三栏（主板/BIOS · 内存条 · 存储设备）
- [ ] `--json` 增加可选的 `hardware` 段（新增字段，不影响现有消费者）
- [ ] 测试：SMBIOS 解析器用构造的字节数组做单元测试（覆盖截断、索引越界）

**验收**：内存速度、槽位数、盘型号与任务管理器一致；在没有任何 SMBIOS 数据的环境下页面显示"不可用"而不会崩。

**技术选择**：不用 WMI。`GetSystemFirmwareTable` 是单次 syscall，免管理员、免 COM、免 `windows` crate，解析成本 ~50 µs，启动时读一次即可。

## M2 Wi-Fi 与网络详情

**要显示的**：SSID、信号强度、连接速率（收/发）、认证方式、IPv4/IPv6 地址、链路速率。

- [ ] `sys/wlan.rs`：`WlanOpenHandle` → `WlanEnumInterfaces` → `WlanQueryInterface(wlan_intf_opcode_current_connection)`
  - 取 SSID（`wlanConnectionProfileDetails` 为空时的兜底）、信号质量 0–100、`rxRate`/`txRate`（kbps）、认证算法、PHY 类型（802.11n/ac/ax）
- [ ] `sys/net.rs` 扩展：`GetAdaptersAddresses(AF_UNSPEC)` 拿每个适配器的 IPv4/IPv6、MTU、操作状态
- [ ] GUI：网络卡片增加"SSID · 信号 ▮▮▮▮ · 10.10.90.64"一行；`硬件` 页加网络适配器明细
- [ ] 无 WLAN 服务/有线网卡时优雅降级（不显示 SSID 行）

**验收**：SSID、信号强度、速率与 `netsh wlan show interfaces` 一致；关闭 Wi-Fi 后界面不报错。

## M3 GPU 监控

**要显示的**：适配器名称、利用率曲线、专用显存占用/上限、共享内存、引擎占用。

- [ ] `sys/gpu.rs`
  - 适配器名：`EnumDisplayDevicesW`（免 COM，取 "Intel(R) Arc(TM) Graphics" 这类描述）
  - 利用率：PDH `\GPU Engine(*)\Utilization Percentage`，实例名形如 `pid_1234_luid_0x…_phys_0_eng_0_engtype_3D`，按 `luid` 聚合（同适配器取各引擎最大值，与任务管理器口径一致）
  - 显存：`\GPU Adapter Memory(*)\Dedicated Usage` / `Shared Usage` / `Dedicated Limit`
  - 节奏：5 秒一次；缓存实例名列表，避免每次全量枚举
- [ ] GUI：新增 GPU 卡片（利用率曲线 + 显存条 + 适配器名），放在 `总览` 第三行或 `硬件` 页
- [ ] 无 GPU 计数器（Win10 1709 以前）时整卡隐藏

**验收**：播放 4K 视频 / 跑 3D 时利用率明显上升；显存占用与任务管理器同量级。

**风险**：GPU 引擎实例可达数百，`PdhGetFormattedCounterArrayW` 的缓冲要复用；聚合时先按 luid 分组再取 max，避免把多进程实例相加导致 >100%。

## M4 进程管理

**要显示的**：进程名、PID、CPU%、私有内存、线程数、句柄数、启动时间；支持按列排序、搜索过滤、结束进程。

- [ ] `sys/process.rs`：`NtQuerySystemInformation(SystemProcessInformation = 5)`
  - 一次 syscall 拿全部进程（x64 偏移：`ImageName` UNICODE_STRING @0x38、`UniqueProcessId` @0x48、`InheritedFromUniqueProcessId` @0x50、`NumberOfThreads` @0x04、`WorkingSetPrivateSize` @0x08、`CreateTime` @0x20、`HandleCount` @0x58）
  - 严格校验：`NextEntryOffset` 单调递增、字符串指针落在缓冲区内、PID 非 0xFFFFFFFF 才保留
- [ ] CPU%：`GetProcessTimes` 增量（`PROCESS_QUERY_LIMITED_INFORMATION`），5 秒窗口；按 PID 缓存上次 kernel+user 与时间戳
- [ ] 结束进程：`OpenProcess(PROCESS_TERMINATE)` + `TerminateProcess`，失败给出中文原因（拒绝访问 / 受保护进程），并区分"需要管理员"
- [ ] GUI：`进程` 页
  - 表头点击排序（CPU / 内存 / 名称 / PID），默认按 CPU 降序
  - 搜索框过滤名称
  - 行右键或末尾按钮"结束"，二次确认对话框
  - 顶部显示 `465 进程 / 8653 线程`
  - 虚拟滚动（只渲染可见行），避免 460 行全量布局
- [ ] 测试：解析器对构造的进程链表做单元测试；CPU% 计算用假数据验证

**验收**：CPU/内存排序与任务管理器一致（CPU ±1%，内存 ±几 MB）；能结束记事本；结束 System 时给出明确失败提示且不崩溃。

**风险**：`SYSTEM_PROCESS_INFORMATION` 是未文档化结构，Windows 版本升级可能变布局。缓解：只读前 0x60 字节的固定字段，加运行期合理性校验（PID/线程数/长度），异常时整体放弃该帧而不是显示垃圾数据。

## M5 托盘 / 自启 / 单实例

- [ ] 开机自启开关：写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（`RegSetValueExW`，免管理员）
- [ ] 单实例：命名 Mutex（`CreateMutexW` 已存在 → 二次启动把已有窗口前置）
- [ ] 托盘图标 + 右键菜单（显示 / 暂停 / 退出）：`Shell_NotifyIconW`，需要一个隐藏窗口与消息循环
  - 若实现成本过高，降级为"最小化到任务栏 + 自启"，托盘留到三期
- [ ] 关闭窗口时的行为可选：直接退出 / 收起到托盘

**验收**：勾选自启后重启生效；二次启动不会开出两个实例。

## 明确不做

| 项目 | 原因 |
| --- | --- |
| 内存"已压缩"、分页/非分页池 | 依赖未文档化的 NT 内存信息类，数值解释容易出错，收益低 |
| 风扇转速 / 每个核心的温度 | 需要内核驱动 + 管理员，一期已确认固件不暴露 |
| 内存时序（CL/tRCD 等） | SMBIOS 里不一定有，且对"监控"价值不大 |
| 跨平台 | 全部实现依赖 Win32，且产品定位就是 Windows |
| 用 WMI 取代 SMBIOS/注册表 | WMI 要 COM + 更多依赖，同样的数据慢一个数量级 |

## 顺序建议

1. **M1 + M2**（1–1.5 天）：直接把你贴的那张任务管理器截图里的硬件与 Wi-Fi 信息补齐，页面框架同时搭好。
2. **M3**（1 天）：GPU 卡片，视觉上最"值钱"。
3. **M4**（1.5–2 天）：最大一块，需要独立表格视图，放最后集中做。
4. **M5**（1 天）：收尾体验。

## 对现有代码的影响

- 新增 `src/sys/{smbios,wlan,gpu,process}.rs`，全部零依赖 FFI。
- `src/gui/` 增加 `pages/`（总览 / 硬件 / 进程）与 `table.rs`（可排序表格），现有六卡片代码不动。
- `Snapshot` 增加 `Option<Hardware>`、`Option<Wifi>`、`Vec<Gpu>`；进程列表体积大，单独线程按 5 秒刷新，不进 `Snapshot`，避免 1 Hz 快照背着 460 条数据。
- 全部新增采集都放在"启动时一次"或"5 秒一次"的节奏，**1 秒的主循环开销不增加**。
